# Data Storage & Vector Catalog: Crocs Visualizer

**Status:** Active  
**Version:** 1.0.0-beta  

---

## 1. Storage Architecture

Crocs Visualizer operates under an account-free, privacy-preserving storage model:

1. **Client State (`localStorage`):** User customization state.
2. **Catalog & Vector Store (Static JSON + Embeddings):** Catalog metadata and vector embeddings served as static assets.

---

## 2. Local Storage Schema

Key: `crocs_visualizer_state_v1`

```typescript
export interface SavedCustomization {
  version: "1.0.0-beta";
  updatedAt: string; // ISO 8601
  shoe: {
    size: "infant" | "kids" | "youth" | "adult";
    colorId: string;
    hexColor: string;
  };
  placements: Array<{
    holeId: string;        // e.g. "HL-01" or "HR-05"
    jibbitId: string;      // ID referencing catalog item
    rotationDeg: number;   // 0 to 360
  }>;
}
```

---

## 3. Vector Embeddings Schema

The Jibbitz catalog includes a lightweight vector index (`catalog/jibbitz-embeddings.json`) generated by the Python pipeline:

```typescript
export interface JibbitzVectorItem {
  id: string;
  name: string;
  type: string;
  image: string;
  measurements?: { widthMm: number; heightMm: number };
  embedding: number[]; // 384-dimensional dense vector
}
```

The frontend uses client-side cosine similarity to match natural-language queries against these embeddings in `< 10ms`.
